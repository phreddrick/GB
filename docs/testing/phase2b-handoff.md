The second, third and fourth reviews (GB2B-03R, GB2B-02R, GB2B-04, GB2B-05, GB2B-06) all concerned the **executable recovery and cleanup procedures** that the remediation rounds had progressively turned into shell, finally a 532-line helper library with a 101-test suite. Rather than a fifth repair, Phase 2B's scope was reduced (section 12.9), and the fifth review's GB2B-07 (Medium: the new safety checker missed four-character fences, indented blocks and interpreter invocations of oddly named files) was corrected narrowly with a permanent regression suite (section 12.10); when the sixth review showed the S5 shell parser still bypassable by a conditional invocation, S5 was replaced by byte-level pinning of the reviewed runner (section 12.11): **the executable recovery automation is retired**, the two procedures are now planning checklists marked NOT APPROVED FOR EXECUTION, an offline safety check guards against runnable recovery or deletion automation reappearing, and recovery and the live RWOP experiment are explicitly deferred to a separately authorised operational-validation stage. ## 8. Security and storage risks carried into the next stages

- **Argo CD write expansion** (StatefulSet create/patch in `gb-dev`) is the largest privilege change of Phase 2; it is paired with the namespace-scoped Role, the AppProject allow-list, manual sync, PSS `restricted` on the Namespace and no API token in the pod. `k8s-helpers` RBAC-REVIEW also wants a ValidatingAdmissionPolicy; that is their call.
- **Admin API on the pod network** (Decision A): token-protected, fenced by NetworkPolicy; the fence is a CNI property that must be verified live (N1 to N13 in `storage-and-network-validation.md`), including the Cilium local-host path (N4) and kubelet probes under default deny (N12). If N12 fails, the design needs a host-entity allow before any sync.
- **RWOP unvalidated**; the access mode is immutable per PVC; the test is ordered before the first server sync and the fallback changes the golden file.
- **`Delete` reclaim** on `longhorn`: deleting the claim destroys the universe; it is the explicit owner-authorised step of the recovery checklist and nothing else.
- **No executable recovery.** Until the operational-validation stage, a `gb-dev` failure (node loss, HALTED engine, crash mid-turn) has no approved recovery path: the response is to preserve evidence, change nothing and escalate. This is accepted because `gb-dev` is disposable until Phase 3a and nothing is deployed yet.
- **CR-18** unchanged: exit codes 2, 3, 6, crashes and node loss mid-turn are recovery cases; `terminationGracePeriodSeconds` 300 > `GB_SHUTDOWN_TIMEOUT` 240 keeps the orderly path in the server's hands.
- **CI write permissions** (next stage): `packages: write` and pull-request creation widen the blast radius of a compromised workflow; keep them per job and pin actions by SHA.
- **Public image**: anyone can pull; nothing secret is inside; digests pin what runs.
- **WebSocket token in the query string** (Phase 1 known item) will traverse Traefik access logs if those are enabled; Traefik is at INFO today.

**Finding (reproduced from Codex's twelve trees).** `safety-check.py` recognised only three-character Markdown fences and detected scripts by extension or executable bit, so five constructions bypassed it while the legitimate read-only case passed: a four-backtick `sh` fence and a four-tilde `bash` fence containing a claim deletion in `deploy.md`; an indented block containing a claim deletion and another containing a forced Pod deletion; and `bash "$HERE/recover.txt"` appended to `run.sh` with the deletion in a `.txt` file inside the tests directory. - *Code blocks* are parsed per CommonMark: an opening run of three **or more** backticks or tildes, closed by a run of the same character at least as long, with an unterminated fence running to the end of the file; plus indented blocks (four spaces or a tab outside a fence, tab and blank-line tolerant). Every command position must be a shell built-in from a short list, an allow-listed script invoked directly or through an interpreter or `env`/`exec`/`command` wrapper (the target resolved from `$HERE`, `$KROOT` or a relative path, **regardless of extension, name or executable bit**), or `go run` of the pinned kubeconform module. It does not interpret shell semantics beyond the small parser described above; a variable it cannot resolve statically is rejected, not understood. It does not inspect files outside its scope, follow links or images, decode encoded or obfuscated text, or read prose instructions that avoid the listed tokens. Markdown constructs it cannot classify are rejected only in the two checklists; in the other operational documents only code blocks are scanned, so prose there is not covered (read-only commands in prose and in code blocks are permitted by design). **No static scan can guarantee the safety of arbitrary shell commands or Markdown documents, and this one does not claim to.** What it does guarantee is narrow and re-runnable: the repository's Phase 2B artifacts contain no script outside the four allow-listed validation files, no reference to the retired library, no destructive or API-evaluating command of the listed kinds in any code block of the operational documents or anywhere in the checklists, and no execution path from `run.sh` to anything but the approved targets.
