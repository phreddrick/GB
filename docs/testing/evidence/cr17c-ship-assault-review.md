## Verdict: stop for one explicit ship-mass disposition

The complete operation appears feasible within the existing checked bbolt architecture, existing buckets and message allocation. No new schema, outbox, commit kind, persistent RNG or command protocol is inherently required. AP is defined as zero by the original dispatcher/helper path, and does not require a new cost decision.

A concrete ship-specific gameplay contradiction remains. C removes the whole attacking party's mass before combat, then *subtracts* returning survivors' mass again on repulse (`source/load.c:1071,1130`). Current Go credits the survivors (`commands_load.go:992`). This is a C sign defect rather than containing-carrier aggregate treatment: the hostile helper has no `landed_on` branch, and valid containing-carrier / peer transfers take the separate ship-recipient branch. C's own `rcv_popn` / `rcv_troops` add arriving mass (`load.c:916–925`).

Let initial mass be M, attacking party N, surviving repulsed party S and caller race mass m. C gives M−(N+S)m on repulse; current Go gives M−(N−S)m. For M=50,N=20,S=15,m=2, C gives −20 while Go gives40. Victory, mutual destruction and total attacker loss remove the entire departing N*m; absorbed bodies remain in the sector and contribute no ship mass.

The earlier approved carrier exemption does not decide this retreat sign. Preserved PR78 Phase0 explicitly says ship retreat mass needs explicit owner disposition before migration (`docs/testing/cr17c-ground-assault-phase0.md:116–120,195`), and the latest task explicitly says the general assault outcomes are not blanket ship-mass approval. Recommend narrowly requesting approval to retain the dormant Go survivor-credit rule, with finite/nonnegative checked mass: repulse M−(N−S)m; all nonreturning outcomes M−N*m. This source review does not authorize that gameplay decision. Do not implement the literal negative-mass C defect or enable the newly reachable operation before disposition.

Thus positive unload initiates combat; zero/omitted with a positive valid complement means the whole complement; no complement must refuse without combat. - Preserve bound-before-default ordering: a preexisting overcapacity ship can make raw0 outside the allowed interval, while an explicit positive unload large enough to remove the excess may still be legal. Do not silently clamp amounts or make all default inputs equivalent regardless of preimage.

Explicit positive VN unload is prohibited; an omitted/default invocation can bypass that check if a corrupt or unusual VN has a positive complement. Existing population rules preserve that order. Document this edge rather than silently adding a blanket VN/type or new default rule. Nonmechanical scope must actively identify relevant defensive AFVs from complete witnesses, including third-party alliance races, before combat draws. PR78 documents C landed() as Docked && WhatDest PLAN, while current Go uses Docked && WhatOrbits PLAN. Preserve PR78's conservative union/current-Go eligibility refusal including armed planetary root AFVs docked to peers; do not call them absent merely because C's helper omitted screening.
